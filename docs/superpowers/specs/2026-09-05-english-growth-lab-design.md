# English Growth Lab 设计文档

## 1. 项目目标

English Growth Lab 是一个运行在 Windows 本机的个人学习仪表盘。它帮助具有 C++、Linux、存储系统和性能分析背景的工程师，通过英文技术内容建立稳定的“阅读 → 听力 → 表达”闭环，并持续拓展架构、AI、科技商业、产品和思维视野。

首个里程碑为 30 天。成功标准如下：

- 每天能在约 30 分钟内完成一条学习记录。
- 每条记录包含阅读、听力、可复用表达和 3–5 句英文总结。
- 每周形成一篇可长期回顾的英文主题复盘。
- 仪表盘能准确展示连续天数、完成率、累计时长、英文输出词数、表达积累与复用、理解度趋势。
- 所有个人学习成果都以可读文件进入 Git，可逐日查看差异并从历史恢复。
- 全新克隆仓库后，可用一条命令启动应用，并从源文件重建查询数据。

## 2. 范围

### 第一版包含

- 30 天固定学习路线。
- 今日任务和手动材料录入。
- 每日阅读、听力、表达与总结记录。
- 每周主题复盘。
- 本地进度仪表盘和历史输出浏览。
- JSON/Markdown 文件持久化。
- SQLite 可重建查询缓存。
- 数据导出与基础自动测试。

### 第一版不包含

- 用户账号、云同步或多人协作。
- RSS 或网页内容自动抓取。
- AI 推荐、翻译、评分或写作点评。
- 自动执行 Git commit。
- 虚拟积分、排行榜或复杂等级系统。

这些能力可以在 30 天闭环被验证有效后再评估。

## 3. 技术架构

仓库采用 npm workspaces 管理前后端：

```text
english-growth-lab/
├── apps/
│   ├── web/                  # React + TypeScript + Vite
│   └── api/                  # Node.js + TypeScript HTTP API
├── content/
│   └── roadmap.json          # 30 天固定路线
├── data/
│   ├── entries/              # 每日 JSON，纳入 Git
│   └── learning.db           # SQLite 查询缓存，不纳入 Git
├── outputs/                  # 每周 Markdown 复盘，纳入 Git
├── docs/
└── package.json              # 一个命令启动前后端
```

### 组件边界

- Web 只负责页面呈现、表单状态和调用 API，不直接访问文件系统。
- API 负责输入校验、源文件读写、统计计算和 SQLite 缓存维护。
- `content/roadmap.json` 是学习路线的唯一事实来源。
- `data/entries/*.json` 和 `outputs/*.md` 是个人学习成果的唯一事实来源。
- SQLite 只用于提高查询速度，删除后可从源文件完整重建。

这种边界允许未来独立增加 RSS 推荐或 AI 反馈，而不改变核心记录格式。

## 4. 数据模型

### 每日记录

每个自然日对应 `data/entries/YYYY-MM-DD.json`：

```json
{
  "date": "2026-09-05",
  "roadmapDay": 1,
  "topic": "Linux Performance",
  "material": {
    "title": "Example article",
    "url": "https://example.com/article",
    "source": "Brendan Gregg"
  },
  "readingMinutes": 10,
  "listeningMinutes": 10,
  "understanding": 3,
  "expressions": [
    {
      "text": "the real bottleneck",
      "meaning": "真正的瓶颈",
      "usedInSummary": true
    }
  ],
  "summary": "The article explains how to locate the real bottleneck.",
  "completedAt": "2026-09-05T08:30:00.000Z"
}
```

约束：

- 日期必须有效且文件名与记录日期一致。
- 阅读、听力分钟数为非负整数。
- 理解度为 1–5。
- 完成记录时至少有 3 个表达和 3 句英文总结。
- 同一天重复保存采用更新语义，不生成重复记录。

### 每周复盘

每周输出为 `outputs/YYYY-Www-review.md`，固定包含：

- 本周主题与材料链接。
- 技术或工程视角。
- 商业、社会或产品视角。
- 自己的英文观点。
- 本周复用的表达。
- 下周调整。

## 5. 用户工作流

### 每日 30 分钟闭环

1. 在“今日”页查看当前路线和推荐来源。
2. 填写实际阅读材料的标题、链接与来源。
3. 阅读约 10 分钟，目标是理解主旨，不逐词翻译。
4. 听同主题内容约 10 分钟。
5. 记录 3–5 个值得复用的英文表达。
6. 用英文写 3–5 句总结，并尽量复用新表达。
7. 填写理解度并完成记录。
8. 应用写入当日 JSON，刷新仪表盘，并提示工作区存在待提交成果。

### 每周输出

周末从本周材料中选择一个主题，分别从技术、商业或社会、个人观点三个角度形成英文复盘。应用生成 Markdown 草稿，用户编辑并确认后保存。

## 6. 页面设计

### 今日

- 当前天数、主题和推荐来源。
- 30 分钟步骤清单。
- 材料、时长、理解度、表达和英文总结表单。
- 自动保存草稿、完成校验和明确错误提示。

### 进度

- 当前连续天数与历史最长连续天数。
- 30 天完成率和日历热力视图。
- 阅读、听力和总学习时长。
- 英文输出累计词数。
- 表达累计数与复用次数。
- 按周聚合的平均理解度趋势。

指标由每日 JSON 实时计算或从 SQLite 缓存读取，缓存结果必须与源文件一致。

### 输出

- 按日期浏览每日英文总结。
- 按周浏览完整复盘。
- 按主题和来源筛选。

### 路线

- 展示 30 天全貌、当前阶段和每日主题。
- 解释每个来源的用途、难度和推荐使用方式。
- 允许打开外部材料；第一版不抓取外部正文。

界面采用简洁、深浅色自适应的仪表盘布局。第一版优先 Windows 桌面浏览器，同时保证窄屏可完成记录。

## 7. 30 天内容路线

### 第 1 周：Linux 与性能

- 主要来源：Brendan Gregg、InfoQ。
- 主题：CPU、内存、IO、perf、eBPF、可观测性、瓶颈定位。
- 目标：利用已有专业知识降低英文理解门槛。

### 第 2 周：工程与架构

- 主要来源：The Pragmatic Engineer、ByteByteGo、InfoQ。
- 主题：架构、分布式系统、工程效率、可靠性、平台工程。
- 目标：从具体系统问题扩展到团队和大规模工程实践。

### 第 3 周：AI、科技与工程讨论

- 主要来源：MIT Technology Review、Hacker News。
- 主题：AI 基础设施、科技影响、工程取舍、真实评论表达。
- 目标：练习从文章主张转向观点比较和讨论。

### 第 4 周：商业、产品与思维

- 主要来源：Stratechery、Paul Graham、Farnam Street。
- 主题：商业模式、公司战略、产品、创业、决策和思维模型。
- 目标：建立“技术 → 产品 → 公司 → 行业 → 社会”的理解链条。

路线文件提供具体到每天的主题和来源，不绑定容易失效的单篇文章 URL。用户每天选择当时可访问且相关的材料。

## 8. 错误处理与数据安全

- API 在写盘前完整校验数据，并返回字段级中文错误。
- 写入采用同目录临时文件加原子替换，避免中途退出造成半写文件。
- 外部链接不可访问时允许更换材料，不影响当天路线和历史数据。
- 应用启动时检查源文件；无效记录被隔离并显示可操作的错误信息。
- SQLite 缺失、版本落后或损坏时自动从 JSON/Markdown 重建。
- 提供完整 JSON 导出，便于仓库之外额外备份。
- 应用只提示 Git 状态，不自动创建提交或改写历史。

## 9. 测试策略

### 单元测试

- 日期、分钟数、理解度和完成条件校验。
- 连续天数、完成率、词数、表达复用和周趋势计算。
- 30 天路线解析。
- 每周 Markdown 生成。

### 集成测试

- 新建、更新和读取每日记录。
- 原子写入失败时保留旧记录。
- 从源文件重建 SQLite。
- 无效源文件的隔离与报告。

### 界面测试

- 完成一条有效的每日记录。
- 阻止提交缺少必要输出的记录。
- 保存后进度指标同步变化。
- 生成并浏览一篇周复盘。

## 10. 验收标准

第一版完成时必须满足：

1. Windows 环境全新克隆后可通过文档中的单一启动命令运行。
2. 用户能完成、修改并重新打开任意一天的记录。
3. 每日成果以可读 JSON 保存，每周成果以可读 Markdown 保存。
4. 仪表盘所有统计值与源文件计算结果一致。
5. 删除 SQLite 后重启应用可以自动恢复全部查询数据。
6. 外部材料不可访问不会导致已有记录丢失或应用崩溃。
7. 核心单元和集成测试通过。
8. Git diff 能清楚展示每天新增或修改的学习成果。
